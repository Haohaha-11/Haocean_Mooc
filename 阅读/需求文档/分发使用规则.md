# 分发使用规则

本文档说明模块 A、模块 C 以及本地联调时模块 B 的分发、配置和运行流程。

## 1. 先理解三个模块的关系

模块 A 是学生端，负责查询开放作业、监控本地作业目录、打包上传作业，并拉取反馈。

模块 C 是教师端，负责查看待批改提交、录入分数和评语，并提交批改结果。

模块 B 是服务端中枢，负责保存作业、接收提交、提供待批改列表、生成反馈。

模块 A 和模块 C 不直接互相通信。完整流程必须经过模块 B：

```text
学生端模块 A -> 服务端模块 B -> 教师端模块 C
教师端模块 C -> 服务端模块 B -> 学生端模块 A
```

所以本地完整联调时，需要同时准备：

```text
module_a_client/
module_b_server/
module_c_controller/
```

## 2. 分发范围

### 2.1 分发给学生端

建议直接分发整个目录：

```text
gongchuang/module_a_client/
```

学生端主要使用：

```text
module_a_client/
├── module_a/
├── scripts/
├── tests/
├── requirements.txt
├── .env.example
└── README.md
```

### 2.2 分发给教师端

建议直接分发整个目录：

```text
gongchuang/module_c_controller/
```

教师端主要使用：

```text
module_c_controller/
├── controller/
├── docs/
├── scripts/
├── tests/
├── requirements.txt
├── .env.example
└── README.md
```

### 2.3 本地完整联调

如果要在本地完整跑通学生提交、教师批改、学生拉取反馈，还需要分发：

```text
gongchuang/module_b_server/
```

模块 B 是 A 和 C 的中间服务。没有模块 B，A 查不到作业，C 也看不到待批改提交。

### 2.4 不要分发运行产物

以下目录和文件是本地运行产生的，不建议分发：

```text
.venv/
__pycache__/
*.pyc
.pytest_cache/
workspace/
data/
feedback_inbox/
feedback_outbox/
logs/
```

## 3. 本地完整运行流程

本地联调建议开三个终端：

```text
终端 1：启动模块 B 服务端
终端 2：运行模块 A 学生端
终端 3：运行模块 C 教师端
```

如果三个模块都在同一台电脑上，服务地址统一使用：

```text
http://127.0.0.1:8000
```

如果模块 B 在另一台电脑上，模块 A 和模块 C 的配置都要写模块 B 那台电脑的 IP：

```text
http://模块B服务器IP:8000
```

## 4. 启动模块 B

打开第一个终端：

```bash
cd /Hao/gongchuang/module_b_server
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python3 -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

如果模块 A 或模块 C 在其他电脑上，需要让模块 B 对外提供访问：

```bash
python3 -m uvicorn app.main:app --host 0.0.0.0 --port 8000
```

可以用下面命令检查模块 B 是否启动成功：

```bash
curl http://127.0.0.1:8000/health
```

## 5. 创建一个开放作业

模块 B 新启动时，数据库里可能没有作业。没有开放作业时，模块 A 执行 `list` 会看不到内容。

可以先创建一个测试作业：

```bash
curl -X POST http://127.0.0.1:8000/v1/assignments \
  -H "Content-Type: application/json" \
  -d '{"action":"CREATE_ASSIGNMENT","timestamp":1,"payload":{"teacher_id":"T001","assignment_id":"home_001","title":"本地测试作业","description":"提交任意文件","deadline":"2026-06-30"}}'
```

这里最重要的是：

```text
assignment_id = home_001
```

学生端本地作业目录必须和这个 `assignment_id` 完全一致。

## 6. 配置并运行模块 A

打开第二个终端：

```bash
cd /Hao/gongchuang/module_a_client
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
```

编辑 `.env`，至少确认下面两项：

```dotenv
MODULE_A_SERVER_URL=http://127.0.0.1:8000
MODULE_A_STUDENT_ID=2024001
```

如果模块 B 不在本机，把 `MODULE_A_SERVER_URL` 改成模块 B 的实际地址：

```dotenv
MODULE_A_SERVER_URL=http://模块B服务器IP:8000
```

然后创建和作业 ID 同名的目录：

```bash
mkdir -p workspace/home_001
```

把学生作业文件放到这个目录里，例如：

```bash
echo "hello" > workspace/home_001/answer.txt
```

查看开放作业：

```bash
python3 scripts/run_client.py list
```

执行一次同步和提交：

```bash
python3 scripts/run_client.py once
```

如果需要后台持续监控学生目录变化：

```bash
python3 scripts/run_client.py watch
```

## 7. 配置并运行模块 C

打开第三个终端：

```bash
cd /Hao/gongchuang/module_c_controller
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
```

编辑 `.env`，正式联调必须使用 HTTP 模式：

```dotenv
CONTROLLER_SOURCE=http
CONTROLLER_API_BASE_URL=http://127.0.0.1:8000
CONTROLLER_TEACHER_ID=T001
```

如果模块 B 不在本机，把 `CONTROLLER_API_BASE_URL` 改成模块 B 的实际地址：

```dotenv
CONTROLLER_API_BASE_URL=http://模块B服务器IP:8000
```

启动教师端 TUI：

```bash
python3 scripts/run_controller.py
```

常用按键：

| 按键 | 功能 |
| --- | --- |
| `p` | 查看 pending 待批改提交 |
| `a` | 查看 approved 视图 |
| `l` | 查看全部提交 |
| `j` / `Down` | 向下选择 |
| `k` / `Up` | 向上选择 |
| `Enter` | 批改当前 pending 提交 |
| `Ctrl+s` | 在批改窗口中提交分数和评语 |
| `Esc` | 关闭批改窗口 |
| `r` | 刷新当前视图 |
| `q` | 退出 |

注意：模块 C 界面里的 `approved` 对应模块 B 里的正式状态 `graded`。这个转换代码已经处理好，教师不需要手动转换。

## 8. 学生端拉取反馈

教师端批改完成后，回到模块 A 终端：

```bash
cd /Hao/gongchuang/module_a_client
source .venv/bin/activate
python3 scripts/run_client.py feedback
```

反馈会保存到：

```text
module_a_client/feedback_inbox/{assignment_id}/submission_{submission_id}_feedback.md
```

例如：

```text
module_a_client/feedback_inbox/home_001/submission_1_feedback.md
```

## 9. 最短流程总结

完整跑通一次的顺序是：

1. 启动模块 B。
2. 在模块 B 中创建开放作业。
3. 配置模块 A 的服务地址和学生学号。
4. 在模块 A 的 `workspace/{assignment_id}/` 里放作业文件。
5. 模块 A 执行 `python3 scripts/run_client.py once` 提交作业。
6. 配置模块 C 为 `CONTROLLER_SOURCE=http`。
7. 模块 C 执行 `python3 scripts/run_controller.py`，进入 TUI 批改。
8. 模块 A 执行 `python3 scripts/run_client.py feedback` 拉取反馈。

## 10. 常见问题

### 10.1 模块 A 看不到作业

优先检查：

```text
模块 B 是否启动
MODULE_A_SERVER_URL 是否正确
模块 B 是否已经创建开放作业
```

### 10.2 模块 A 没有提交文件

检查作业目录名是否和 `assignment_id` 完全一致。

例如模块 B 的作业 ID 是：

```text
home_001
```

那么模块 A 的目录必须是：

```text
workspace/home_001/
```

### 10.3 模块 C 的 pending 列表为空

优先检查：

```text
模块 B 是否启动
CONTROLLER_SOURCE 是否为 http
CONTROLLER_API_BASE_URL 是否正确
模块 A 是否已经成功提交作业
提交是否已经被批改过
```

### 10.4 教师端分数提交失败

模块 B 当前要求分数是 0 到 100 的整数，不要输入小数。

### 10.5 本机和多机部署的区别

如果 A、B、C 都在本机：

```text
http://127.0.0.1:8000
```

如果 B 单独部署在一台电脑或服务器上：

```text
http://模块B服务器IP:8000
```

模块 A 的 `MODULE_A_SERVER_URL` 和模块 C 的 `CONTROLLER_API_BASE_URL` 都要指向同一个模块 B 地址。
